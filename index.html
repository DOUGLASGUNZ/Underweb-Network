OPEN BETA HISTORY

UnderWeb Network Updates

The major fixes, systems and milestones that turned the first staff beta into the Network running now.

CURRENT: 0.8.0 OPEN BETA RC1
NOW
OPEN BETA RC1 • STABILIZATION

The Network is becoming a platform.

UnderWeb now runs real member identities, creator access, moderated media, events, staff operations, hardened permissions, Network Pulse and persistent profile cosmetics. Current beta work is focused on reliability, mobile parity and catching permission edge cases before wider access.

OPEN BETASECURITYMOBILENETWORKCREATORS
LATEST
MEMBER PROFILES

Members are members first

Removed leftover creator-role dependencies from ordinary profile editing. Authenticated members can maintain their basic Network identity after onboarding while creator-only fields and tools remain permission-gated.

LATEST
NETWORK PULSE

The Network has a heartbeat

Expanded Pulse to support meaningful Network activity including published events, profile updates and cosmetic discoveries. Profile-edit activity is limited to one feed entry per member per hour to prevent spam.

LATEST
EVENTS

Featured Event reliability

Reworked UP NEXT selection to prioritize the nearest approved future event instead of stale active records. Featured artwork now follows the selected event and falls back cleanly when no poster exists.

0.8
SECRET COSMETICS

Persistent profile cosmetics

Added a seven-piece secret cosmetic collection, Cosmetic Locker, persistent unlock/equip state, animated profile presentation and public-profile rendering. Discovery paths were audited for mobile accessibility. Unlock methods remain intentionally undocumented.

0.8
PROFILE RENDERER

Frames rebuilt properly

Rebuilt cosmetic attachment around the real rendered avatar so profile refreshes no longer destroy or misalign equipped frames. The stable attachment architecture is now independent from replaceable avatar contents.

0.7.9
SECURITY HARDENING

Permissions moved beyond hidden buttons

Hardened internal RPC access, role authority, projects, applications, invitations and creator media policies. Creator authorization is enforced by backend role state rather than frontend assumptions.

0.7.9
MEDIA REVIEW

Secure creator showcase moderation

Creator uploads enter private pending storage first. Staff approval promotes accepted media into the public showcase, while ordinary clients cannot write directly to public creator-showcase storage.

0.7.9
CREATOR ACCESS

Creator means approved creator

Corrected Network Gallery and creator-feature access so an ordinary member is not treated as a creator just because a profile record exists. Active creator roles are now the authority.

0.7.3
IDENTITY

Roles, titles and presentation

Expanded profile identity, role presentation and premium title treatments while cleaning up duplicate role display across scopes. Scope still controls authority without cluttering profiles with repeated titles.

0.7.2
NETWORK EXPANSION

Connected network tools

Added Event Control, Network Gallery, Partner Hub, notifications, Connected Accounts and the proof-of-control VRChat verification workflow.

0.7.1
MEDIA

Real event + project artwork

Added Supabase Storage-backed flyer and cover uploads so events and projects can use real Network media instead of placeholder presentation.

0.6.3
PROJECT RECRUITING

Build the Crew

Added project slots, applications, creator invitations, review workflows and recruiting management for collaborative Network projects.

EARLY
ONBOARDING

Member and creator identity separated

Early beta exposed a core architecture problem: ordinary members were being pushed through creator-profile assumptions. Onboarding was reworked so every account starts as a Network member and creator/staff access is layered on through real roles.

EARLY
AUTH

Persistent Network accounts

Established email authentication, persistent sessions and display-name onboarding so identity survives reloads, logouts and device use without exposing passwords to Network staff.

NEXT
BETA ROADMAP

Integration + continued stabilization

Continue mobile and permission testing, strengthen Network activity and staff workflows, then build deeper Discord and VRChat integration on top of the same verified identity and authority model.

CONNECTED ACCOUNTS.

Claims are not trusted automatically. Discord will use OAuth. VRChat uses proof-of-control verification so nobody can simply paste somebody else's profile.

VRCHAT

NOT CLAIMED

Paste your VRChat user profile. UnderWeb gives you a temporary verification code to place in your VRChat bio/status. This proves you control the profile without giving UnderWeb access to your VRChat account.

PRIVACY-FIRST VERIFICATION

UnderWeb will never ask for your VRChat password, 2FA code, authentication token, or session data. We use a temporary public verification code specifically so you do not have to give us sensitive account information.

YOUR VERIFICATION CODE —

Temporarily put this exact code in your VRChat bio/status, then press Verify My Account. For now, this sends the claim to staff for proof-of-control review. The verification system is structured so this check can be automated later without changing how your identity is stored.

Once UnderWeb shows your account as VERIFIED, you can immediately remove this code from your VRChat profile.
DISCORD

CHECKING CONNECTION…

Connect Discord to verify ownership for UnderWeb bot and spider features. Disconnect here to remove the identity and bot link. Discord server roles are managed separately. UnderWeb never asks for your Discord password.
